给定每篇论文的引用次数，求最大的 H 指数：至少有 h 篇论文的引用次数不小于 h。排序后从高引用论文开始计数，第 count 篇论文若被引用至少 count 次，就能把候选答案提升到 count。

<!-- more -->

## 题目与关键约束

LeetCode 274「H 指数」输入数组 `citations`，其中每个元素表示一篇论文的引用次数。返回最大的整数 h，使得至少 h 篇论文各自至少被引用 h 次。

例如 `[3, 0, 6, 1, 5]` 排序后为 `[6, 5, 3, 1, 0]`。前三篇都至少被引用 3 次，但第四篇只有 1 次，所以答案是 3。

## 思路与推导

先将引用次数从高到低排序。按顺序考察第 `count` 篇论文：若它的引用数 `c >= count`，因为前面的论文引用数不低于它，前 `count` 篇都至少有 `count` 次引用，候选 H 指数可更新为 `count`。一旦 `c < count`，后面的引用数只会更低，不可能再满足更大的候选值，可以停止。

这里的比较关键是当前论文的名次 `count`，而不是已经成立的答案 `h`。例如 `[1, 1]`：第一篇满足 h=1；第二篇要把答案提高到 2，就必须有至少 2 次引用，但实际只有 1 次。因此条件必须是 `c >= count`。

## 代码与复杂度

```python
class Solution:
    def hIndex(self, citations: list[int]) -> int:
        citations.sort(reverse=True)

        h = 0
        for count, c in enumerate(citations, start=1):
            if c >= count:
                h = count
            else:
                break

        return h
```

设论文数为 n，排序时间为 O(n log n)，扫描为 O(n)，整体时间复杂度为 O(n log n)。Python 原地排序；除排序实现自身的辅助空间外，算法只使用常数个变量。练习中用户反馈“通过”，记录为平台已通过。

## 本次复盘

最初的想法是从最小引用数开始找不满足的位置，随后改为从高到低排序，从前缀长度直接判断候选 h。这个顺序让“至少 h 篇论文各有至少 h 次引用”的定义自然对应第 h 篇论文。

原代码用已累计的 `h` 比较 `c`，边界上会错把 `[1, 1]` 算成 2。应使用当前考察名次 `count` 判断 `c >= count`。遇到“至少 k 个元素达到 k”的条件时，可以考虑排序后按名次扫描，并用小数组验证等号边界。
