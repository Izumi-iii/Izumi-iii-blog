给出五个坐标点，判断能否选出四个，组成边平行于坐标轴的矩形。关键不是枚举四个点的排列，而是先选两个对角顶点，确定另外两个顶点，再用集合检查它们是否存在。

<!-- more -->

## 题目与关键约束

每组输入一行十个整数，每相邻两个数表示一个点的横、纵坐标。目标是判断五个点中是否包含一个宽、高均大于零，且边平行于坐标轴的矩形。

例如，五个点为 `(2, 3)、(6, 8)、(2, 8)、(6, 3)、(9, 9)` 时，前四个点可以组成矩形。

本次没有提供原题链接、平台名称和题号，也没有完整题面的输入输出约定。下面沿用练习代码的假设：第一行是测试组数，每组一行十个整数，输出小写 `yes` 或 `no`。提交前仍需核对原题是否采用这个格式。坐标按整数处理，不要求为正，也不依赖五个输入点互不相同。

## 思路与推导

在引导中采用的切入点是：轴对齐矩形只有两个不同的横坐标、两个不同的纵坐标，其顶点必须覆盖这四种组合。

任取两个点 `(x1, y1)` 和 `(x2, y2)`。如果它们是矩形的对角顶点，另外两个顶点就只能是 `(x1, y2)` 和 `(x2, y1)`。例如选中 `(2, 3)` 和 `(6, 8)`，另两点是 `(2, 8)` 与 `(6, 3)`，横坐标始终在前，不能把第二个点写成 `(3, 6)`。

还需要排除退化情况：必须满足 `x1 != x2` 且 `y1 != y2`。否则四个组合不能形成四个不同的顶点，宽或高会变成零。

实现时，用列表 `points` 保存五个点，方便按下标枚举；每个点用整数元组表示，例如 `(2, 3)`。再创建集合 `point_set`，用于查找某个坐标是否存在。列表支持按位置取点，集合负责成员查询。整数元组可以作为集合元素，直接用列表 `[2, 3]` 则不行。

枚举下标 `i` 和 `j`，让 `j` 从 `i + 1` 开始，每对输入点只检查一次。五个点一共只有十对。若找到合适的对角线，就把 `found` 设为真，结束搜索。

为什么不会漏掉答案？任何符合要求的矩形都有一对对角顶点，它们一定会被枚举到；另外两个顶点也一定在集合中。反过来，若两个坐标均不同，且另两种组合都存在，就确实得到了四个不同的矩形顶点。因此条件既充分又必要。

## 代码与复杂度

以下为按上述输入输出假设整理的 Python 代码，包含练习后由助手提出的修正：

```python
n = int(input())

for _ in range(n):
    nums = list(map(int, input().split()))

    points = []
    for i in range(0, 10, 2):
        points.append((nums[i], nums[i + 1]))

    point_set = set(points)
    found = False

    for i in range(5):
        for j in range(i + 1, 5):
            x1, y1 = points[i]
            x2, y2 = points[j]

            if x1 != x2 and y1 != y2:
                if (x1, y2) in point_set and (x2, y1) in point_set:
                    found = True
                    break

        if found:
            break

    print("yes" if found else "no")
```

本题每组固定五个点，时间和辅助空间均为 `O(1)`；若有 T 组，总时间为 `O(T)`，逐组处理，辅助空间不随组数增长。若将方法推广到 m 个点，在集合查询平均为 `O(1)` 的假设下，时间为 `O(m²)`，辅助空间为 `O(m)`，输出逐行写出，不累计保存。

上述完整程序已本地执行六组自建测试：存在矩形、五点共线、横坐标全部相同、重复点且缺少顶点、含负坐标和重复点的有效矩形，以及仅有旋转矩形。结果均符合预期，混合多组时每组只输出一行。没有原题样例或平台通过证据，不能据此声称已通过评测。

## 本次复盘

1. **坐标交换与容器理解。** 最初推算另两个顶点时，把其中一个写成了 `(3, 6)`；经提示后明确，交换的是两个点的纵坐标，坐标内部仍保持“横在前、纵在后”。随后补充理解了列表存多个点、元组存一个点，以及 `x, y = points[i]` 的拆包写法。

2. **输入函数需要调用。** 截图中写的是 `int(input)`，传入的是函数本身；应改成 `int(input())`，先读取字符串，再转换成整数。这是代码检查发现的问题，没有对应的实际报错或评测记录。

3. **搜索结果与输出次数。** 原代码找到矩形就打印 `yes`，循环后又无条件打印 `no`，会让同一组产生多行甚至矛盾结果。修正为用 `found` 记录状态，找到后退出搜索，最后统一输出。一个 `break` 只退出一层循环，因此外层也要检查 `found`。

下次遇到“几个点能否构成某种图形”，先问：能否用更少的点确定剩余顶点？写完搜索后再检查：每组是否恰好输出一次，是否排除了面积为零的退化情况？
