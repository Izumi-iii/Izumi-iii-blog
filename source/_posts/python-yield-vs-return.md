## 一、面试回答：一个结束，一个暂停

**`return` 结束当前函数调用并返回结果；`yield` 产出一个值，暂停生成器的执行，并保留局部变量和执行位置，供下次继续。**

在普通 `def` 函数自己的函数体中出现 `yield`，这个函数就成为生成器函数。调用它时拿到的是生成器对象，函数体暂时不执行；使用 `next()` 或 `for` 消费它时，才逐步运行。

因此，需要一次性交付最终结果时用 `return`；需要按需产生一系列结果时，可以使用 `yield`。在 Agent 开发中，读取模型输出流、逐条处理检索结果，都适合用生成器组织数据。

但 `yield` 不等于异步，也不等于开线程。**它提供暂停和恢复的能力，能否非阻塞地等待网络，要看底层调用方式。**

## 二、执行过程：生成器为什么能继续？

| 对比项 | 普通函数的 return | 生成器中的 yield |
|---|---|---|
| 执行效果 | 结束当前调用 | 产出值并暂停 |
| 调用函数得到什么 | 函数返回值 | 生成器对象 |
| 执行状态 | 本次调用结束 | 挂起时保留局部变量和位置 |
| 多次获取结果 | 通常需要重新调用 | 可反复 next，直到耗尽 |
| 常见用途 | 返回一个结果或完整集合 | 按需产生一串结果 |

例如，生成器循环运行到 `yield token` 时，会把这个 token 交给消费者，并暂停在这里。下一次调用 `next()`，会从暂停位置继续，进入后续循环。

**生成器可以同时包含 `yield` 和 `return`。** 两者分工不同：`yield` 交付迭代中的元素，`return` 标记迭代结束。在同步生成器中，`return value` 的值保存在结束异常的 `StopIteration.value` 中，不会成为下一个迭代元素。

生成器自然运行到函数结尾，也会结束迭代。`for` 会正常处理这个结束信号；手动调用 `next()` 时，耗尽就会遇到 `StopIteration`。

另外，判断是不是生成器函数，取决于它自己的函数体是否包含 `yield`，而不是这次执行是否真的走到了那一行。

## 三、一个例子：一次返回和分次产出

下面用两个字符串片段模拟模型输出，不涉及真实网络调用：

```python
def complete():
    return ["你", "好"]


def stream():
    print("开始生成")
    for token in ["你", "好"]:
        yield token
    return "完成"


print(complete())
g = stream()  # 这里只创建对象，不打印“开始生成”
print("生成器已创建")
print(next(g))
print(next(g))
try:
    next(g)
except StopIteration as exc:
    print("结束信息：", exc.value)
print(list(g))  # 已耗尽，得到空列表
```

输出顺序是：完整列表、生成器已创建、开始生成、你、好、结束信息与完成，最后是空列表。注意“开始生成”出现在第一次 `next()` 时。

在真实 Agent 服务中，上游模型客户端产生一个片段，生成器就可以向下游产出一个片段。消费者可以边收到边展示，而不必等完整答案全部到齐。

不过，**生成器不会把已经完整生成的文本，自动变成真正的模型流式输出**。如果先等待完整模型结果，再切成片段 `yield`，只是分段发送，仍然要先等待完整结果。

内存优势也有前提：生产者不能预先缓存所有数据，消费者也不能又用 `list(generator)` 一次性全部收集。生成器仍会保留自己引用的对象，不能笼统说“完全不占内存”。

## 四、三个高频追问

**Q1：生成器可以重复遍历吗？**

同一个生成器对象耗尽后，不能从头重新遍历。需要重新调用生成器函数，创建新对象。列表通常可以多次遍历，这一点与生成器不同。

**Q2：`yield` 和 `await` 是一样的吗？**

不是。`yield` 向生成器的消费者产出元素；`await` 等待一个可等待对象的结果，在需要等待时允许异步任务挂起。现代 Python 里不要把普通生成器直接当成 asyncio 协程。

`async def` 中使用 `yield` 会形成异步生成器，通常通过 `async for` 消费；它不能像同步生成器那样使用带返回值的 `return value`。

**Q3：消费者中途停止，清理代码会立即执行吗？**

不一定。只是在循环里 `break`，不能保证挂起生成器的清理立刻完成。涉及文件、连接等资源时，应明确管理生命周期；同步生成器的 `close()` 可以触发相应清理，异步生成器有 `aclose()`。

复习时可以按这个顺序复述：**调用先创建生成器 → 消费时开始执行 → yield 产出并暂停 → 下次继续 → return 或函数结尾结束。**
