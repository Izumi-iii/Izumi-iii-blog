## 题目与关键约束

- **平台与题号**：LeetCode [15. 三数之和](https://leetcode.cn/problems/3sum/)
- **输入输出**：给定一个整数数组 `nums`，找出所有和为 0 且不重复的三元组 `[nums[i], nums[j], nums[k]]`（满足下标互不相同）。
- **关键约束**：
  - $3 \le \text{nums.length} \le 3000$
  - $-10^5 \le \text{nums}[i] \le 10^5$
  - **答案中不能包含重复的三元组**（核心难点）

例如输入 `nums = [-1, 0, 1, 2, -1, -4]`，满足三数之和为 0 的不重复三元组为 `[[-1, -1, 2], [-1, 0, 1]]`。

## 思路与推导

直接枚举三个下标的朴素暴力法时间复杂度为 $O(N^3)$，在 $N = 3000$ 的规模下必然超时，且去重极其繁琐。

本题可以通过“**先排序，再降维**”转化为已掌握的有序数组对撞双指针问题：
1. **降维思想**：由于 $a + b + c = 0 \iff b + c = -a$，若先对数组排序，固定第一个数 $a = \text{nums}[i]$，问题便退化为在下标区间 $[i + 1, N - 1]$ 内寻找两数之和等于 $-a$ 的双指针子问题，时间复杂度成功降低至 $O(N^2)$。
2. **贪心剪枝**：排序后数组单调非递减。若当前固定的第一个数 $\text{nums}[i] > 0$，则后续任何元素均大于 0，三个正数之和不可能等于 0，可直接终止外层循环。

### 去重逻辑与陷阱

题目要求“不可包含重复的三元组”，去重必须在两层循环中严格落实：
- **外层固定数去重**：若当前数与前一个数相同（`i > 0 and nums[i] == nums[i - 1]`），由于以该数值为起点的所有有效组合在上一轮均已搜尽，必须直接 `continue` 跳过。
  - *注意反例*：不能写成向后比较（`nums[i] == nums[i + 1]`），否则会误杀形如 `[-1, -1, 2]` 这样三元组内部允许存在相同元素的合法答案。
- **内层双指针去重**：当找到一组满足三数之和为 0 的解并加入答案后，若左右指针后续相邻元素与当前值相同，必须跳过所有连续重复值（`nums[left] == nums[left + 1]` 和 `nums[right] == nums[right - 1]`），最后再收缩一步寻找下一组不同解。

## 代码与复杂度

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        answer = []
        nums.sort()

        for i, num in enumerate(nums):
            # 剪枝：若首个元素已大于 0，后续元素均大于 0，三数之和必大于 0
            if num > 0:
                break

            # 首元素去重：跳过与前一个数相同的元素，避免重复搜索
            if i > 0 and nums[i] == nums[i - 1]:
                continue

            left = i + 1
            right = len(nums) - 1
            target = -num

            while left < right:
                s = nums[left] + nums[right]
                if s < target:
                    left += 1
                elif s > target:
                    right -= 1
                else:
                    answer.append([num, nums[left], nums[right]])

                    # 仅在命中有效解后，跳过左右指针的重复元素
                    while left < right and nums[left] == nums[left + 1]:
                        left += 1
                    while left < right and nums[right] == nums[right - 1]:
                        right -= 1

                    # 双指针向内收缩，寻找下一组解
                    left += 1
                    right -= 1

        return answer
```

- **时间复杂度**：$O(N^2)$，其中 $N$ 为数组长度。排序耗时 $O(N \log N)$；外层循环遍历 $N$ 次，内层双指针总计最多移动 $N$ 步，双层循环耗时 $O(N^2)$。综合复杂度为 $O(N^2)$。
- **空间复杂度**：$O(1)$ 或 $O(\log N)$（取决于底层排序实现的辅助栈空间）。除存储答案所需空间外，仅使用了常数个指针变量。

## 本次复盘

1. **原想法**：将剪枝条件写为 `if num >= 0: break`。
   - **反例**：对于 `[0, 0, 0]`，当遍历到首个 0 时就会被过早截断，丢失唯一的合法三元组。
   - **修正**：严格限制剪枝阈值为大于 0（`if num > 0: break`），允许以 0 为起点的非负解正常参与计算。
2. **原想法**：将双指针两数之和 `s = nums[left] + nums[right]` 写在 `while left < right:` 外部。
   - **原因**：误将静态赋值置于循环体前，导致 `left` 或 `right` 移动后和 `s` 无法动态更新。
   - **修正**：移入内层循环体首部，保证每次移动指针后均基于最新位置核算总和。
3. **原想法**：将双指针的去重 `while` 与收缩逻辑写在 `if-elif-else` 分支之外。
   - **反例**：当和过小时（`s < target`），原期望仅通过 `left += 1` 增大总和，但外部逻辑会无差别触发 `right -= 1`，破坏了双指针的收缩单调性。
   - **修正**：去重与双向收缩必须且仅能归属于命中答案的 `else:` 分支内部。
