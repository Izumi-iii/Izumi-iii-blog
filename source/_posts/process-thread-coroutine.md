> 学习目标：能口述三者的区别，并解释 Agent 工具调用时如何选型。建议用 10～15 分钟阅读、理解代码并复述。

## 一、面试回答：先掌握这一段

**进程侧重资源分配与隔离，线程是操作系统调度执行的基本单位之一，协程是可以暂停和恢复的执行方式。**

不同进程通常拥有独立的地址空间，可以利用多核并行，但启动和通信成本较高。同一进程内的线程共享内存，每个线程有自己的栈和执行状态，通信方便，但访问共享数据需要同步。

以 Python `asyncio` 为例，多个协程任务由事件循环在一个线程内协作调度。当任务等待异步 I/O 时，可以让出执行机会，推进其他任务，因此适合大量网络等待，但不能直接加速 CPU 计算。

在常见的启用 GIL 的 CPython 中，**纯 Python 重计算通常考虑多进程；同步阻塞 I/O 可以使用线程池；支持异步调用的网络 I/O 可以使用协程。**

## 二、核心区别：一张表加三个原理

先区分两个词：**并发**是多个任务在一段时间内共同推进；**并行**是多个任务在同一时刻执行。单核可以并发，多核可以提供并行能力。

以下协程特指 Python `asyncio` 的常见用法。

| 对比维度 | 多进程 | 多线程 | 协程 |
|---|---|---|---|
| 内存关系 | 地址空间通常独立 | 共享进程内存 | 同一事件循环中的任务共享内存 |
| 谁负责调度 | 操作系统调度其线程 | 操作系统 | 事件循环协作调度 |
| 创建和切换开销 | 通常较高 | 通常低于进程 | 通常较低 |
| 多核并行 | 可以 | 可以，受运行时和任务影响 | 单线程事件循环本身不提供 |
| 典型用途 | 重计算、进程隔离 | 同步 I/O、阻塞 SDK | 异步网络请求 |
| 主要代价 | 通信、序列化、内存占用 | 数据竞争、锁和线程管理 | 阻塞事件循环、任务管理 |

**1. 为什么进程隔离更强，通信更麻烦？**

因为默认不共享地址空间。子进程修改普通列表，不会自动改变父进程中的列表，需要通过队列、管道或共享内存交换数据。大对象传递可能带来序列化和复制成本，所以小任务不一定适合多进程。

**2. 为什么线程需要锁，GIL 又是什么？**

线程共享对象。“读取余额 → 计算 → 写回”包含多个步骤，两个线程可能交错执行并覆盖结果，需要适当同步。

GIL 是 CPython 的全局解释器锁。在常见的启用 GIL 的构建中，同一解释器内通常只有一个线程执行 Python 字节码，因此多线程通常不能加速纯 Python 的重计算。

但等待 I/O 时通常会释放 GIL，一些原生扩展在计算时也会释放它，所以不能说“Python 多线程永远不能并行”。Python 3.13 起还提供可禁用 GIL 的 free-threaded 构建，需要结合实际环境判断。**GIL 也不保证多步骤业务逻辑的线程安全。**

**3. 为什么协程适合网络请求？**

网络请求往往主要在等待。任务 A 等响应时，事件循环可以推进任务 B，无需为每个请求创建一个线程。

但协程需要协作让出执行机会。长时间计算、`time.sleep()` 或同步网络请求都会阻塞当前事件循环线程；仅给函数加上 `async def` 不会让内部调用自动变成异步。`await` 等待的对象已经就绪时，也不一定发生任务切换。

## 三、Agent 开发：怎么选，怎么用？

选型时先看耗时来源，以及工具是否支持异步：

- **LLM API、搜索、远程数据库**：通常以网络等待为主，客户端支持异步时，可以使用协程。
- **只有同步接口的工具 SDK**：可以通过线程池执行，例如 `await asyncio.to_thread(sync_tool, argument)`，同时确认线程安全和超时配置。
- **大量纯 Python 计算**：可以考虑进程池，但要评估通信和内存成本。本地模型推理还受 GPU、批处理和推理框架影响，不能直接套用这个结论。

例如，天气查询和交通查询相互独立，可以并发；生成出行建议依赖两者结果，应等待查询完成后再执行。

下面使用异步等待模拟三个独立工具，最多同时运行两个。代码可在 Python 3.11+ 运行：

```python
import asyncio


async def main():
    limit = asyncio.Semaphore(2)

    async def call_tool(name):
        async with limit:
            await asyncio.sleep(1)  # 模拟异步网络等待
            return f"{name}完成"

    async with asyncio.TaskGroup() as group:
        tasks = [
            group.create_task(call_tool(name))
            for name in ["天气查询", "交通查询", "酒店查询"]
        ]

    print([task.result() for task in tasks])


if __name__ == "__main__":
    asyncio.run(main())
```

每个任务等待约 1 秒，两个先执行，一个随后执行，总耗时约 2 秒。实际调用时，需要换成支持异步的工具客户端。

代码只需要抓住三点：

1. **`create_task()` 组织并发**：如果依次写 `await call_tool(...)`，这些调用仍然串行。
2. **`Semaphore(2)` 限制同时执行的数量**：它不等于 API 的每分钟请求数或 Token 限流。
3. **`TaskGroup` 管理任务生命周期**：一个任务发生普通未处理异常时，会取消组内其他未完成任务；允许部分失败时，需要另行处理。

项目中还要补上超时、有限重试和取消后的清理。并发可以重叠等待，但也可能更快耗尽 API 配额。

## 四、高频追问：能解释这三题就够了

**Q1：单核 CPU 上，多线程还有意义吗？**

有。一个线程等待 I/O 时，其他线程仍可推进，改善吞吐和响应性；如果全是计算，额外调度反而可能降低性能。

**Q2：单线程协程也会有数据竞争吗？**

会。如果“读取状态 → await → 修改状态”中间挂起，其他任务可能插入修改同一份状态。必要时使用 `asyncio.Lock`；数据库并发更新还需要事务等机制。

**Q3：三者可以混用吗？**

可以。例如服务用多个进程，每个进程通过事件循环处理网络请求，再用线程池调用同步工具。但总线程数、连接数和内存会叠加，需要统一控制。

**复习自测**：合上文章，用一分钟说清三者的内存关系、调度方式，以及你会如何并发执行两个独立的 Agent 工具。
