## 一、面试回答：混合的是检索信号

“独立检索”不是唯一标准术语。本文按 RAG 场景，将它理解为**只用一种检索策略的单路检索**，例如只用关键词检索，或只用向量检索；如果指多个知识库分别检索，那属于另一个维度。

**混合检索同时使用多种检索信号，常见组合是 BM25 关键词检索与向量检索，再把候选结果去重、融合排序，必要时进一步重排。**

关键词检索善于处理术语、编号和原文词项；向量检索通过 embedding 表达文本语义，能找到措辞不同但含义接近的内容。两路可以互补，但融合质量仍需验证。

混合不是简单把两个列表拼起来，也通常不是把文本和向量拼在一起。**真正的重点是：如何让不同检索器产生的候选，形成一份统一的排序。**

## 二、实现流程：从两路召回到一份结果

以“报错 E1042，怎样恢复数据库连接？”为例：

- BM25 路径可以利用 `E1042`、数据库、连接等词项召回相关文档；具体效果受分词、字段和查询配置影响。
- 向量路径把问题编码成向量，可能召回“连接池断开后的重连机制”等语义相关片段。

常见流程是：**切分并建立索引 → 同一问题分别检索 → 每路取 Top-N → 按稳定 ID 对齐候选 → 融合排序 → 可选 rerank → 选 Top-K 放进上下文。**

两路应尽量基于一致的文本切块和文档版本，并使用相同的权限、租户等过滤条件。否则不同结果可能无法对应，或者候选里混入不可访问内容。

常用融合方法有两类：

| 方法 | 融合依据 | 主要注意点 |
|---|---|---|
| 加权分数融合 | 各路经过适当处理的相关性分数 | 分数尺度、权重和归一化方式需要验证 |
| RRF 排名融合 | 文档在各路结果中的名次 | 不使用原始分数大小，受候选窗口和排名影响 |

**加权融合**可以写成 `score = α × lexical_score + (1-α) × vector_score`，但这里应使用经过合理校准或归一化的分数。BM25 与向量相似度通常不在同一尺度，直接相加可能让一路主导。权重也不是把两路各取一半结果。

**RRF（Reciprocal Rank Fusion）**则按排名累加：文档在某一路排名为 r，就获得 `1 / (k + r)` 的贡献；没有进入该路候选集，贡献为 0。r 从 1 开始，k 是平滑常数。

例如 A 在两路分别第 1、第 3，B 分别第 2、第 1；取 k=60 时，A 约为 0.03227，B 约为 0.03252，所以 B 排在前面。它获得了两路共同的较高排名支持。

## 三、最小代码：实现两路 RRF 融合

下面假设 BM25 和向量检索已完成，输入是按相关性降序排列的 chunk ID。代码只演示融合，不实际建立索引、计算 embedding 或发起检索。

```python
from collections import defaultdict


def rrf_merge(rankings, k=60, top_k=4):
    scores = defaultdict(float)
    for ranking in rankings:
        # 同一路的相同 ID 只计一次
        unique_ids = dict.fromkeys(ranking)
        for rank, chunk_id in enumerate(unique_ids, start=1):
            scores[chunk_id] += 1 / (k + rank)
    return sorted(
        scores.items(),
        key=lambda item: (-item[1], item[0]),
    )[:top_k]


bm25_results = ["A", "B", "C"]
vector_results = ["B", "D", "A"]

for chunk_id, score in rrf_merge([bm25_results, vector_results]):
    print(chunk_id, round(score, 5))
```

结果依次是 B、A、D、C，对应约 0.03252、0.03227、0.01613、0.01587。相同 chunk 在两路出现时会累加贡献，最终只保留一个条目。

这里 k=60 只是演示用的常见取值，不是固定最优参数。每路召回多少、最终保留多少，都需要结合知识库和评测调整。

还要区分 **fusion 和 rerank**：融合利用已有分数或名次组合候选；模型重排则重新评估“问题—片段”的相关性。可以先融合再用 cross-encoder 等重排，重排不是混合检索的必选步骤。

## 四、三个高频追问

**Q1：只对向量检索结果做 rerank，算混合检索吗？**

通常不算这里讨论的关键词与向量混合检索，因为它只有一条召回路径。它属于“向量召回 + 重排”的多阶段流程。多阶段不自动等于多路混合。

**Q2：两路都没召回的内容，融合或重排能找回来吗？**

不能。融合和常规重排只处理已有候选。此时应排查切块、索引更新、embedding、查询改写、分词、过滤条件或候选数量，而不是只调融合权重。

**Q3：怎样判断混合检索真的更好？**

用相同数据和问题集比较关键词单路、向量单路和混合方案，覆盖编号查询、术语查询、自然语言改写等类型。观察 Recall@K、MRR 或 nDCG，同时检查延迟、成本和最终答案的证据支持情况。

增加一路不保证每条问题都改善。候选噪声可能增加，检索阶段即使并行，也仍有融合、重排和更多数据处理开销；检索是否相关与答案是否有据，都需要评估。

复习时可以沿着这个例子讲：**关键词匹配报错编号，向量寻找语义相关说明，RRF 合并两路排名，再选择证据交给模型。**
