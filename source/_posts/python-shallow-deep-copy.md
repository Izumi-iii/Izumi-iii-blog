## 一、面试回答：先区分赋值和拷贝

**赋值通常只是建立新的名字绑定；浅拷贝新建外层容器，但内部元素仍引用原来的对象；深拷贝则按照对象的拷贝规则，递归处理内部对象。**

对于普通的嵌套列表、字典，浅拷贝后修改共享的内部可变对象，会影响原数据；深拷贝后，这些内部可变对象通常已经分离，修改副本不会影响原数据。

常见写法是 `copy.copy(obj)` 和 `copy.deepcopy(obj)`。内置列表的 `list.copy()`、完整切片 `[:]`，以及内置字典的 `dict.copy()`，也属于浅拷贝。

在 Agent 开发中，复制会话消息、配置或分支状态时，关键是确认**哪些对象需要独立，哪些对象应当共享**，而不是遇到状态就一律深拷贝。

## 二、关键原理：复制容器，还是复制内部对象？

假设原状态是一个字典，里面的 `messages` 是列表，列表元素又是消息字典。这里有三层对象：外层字典、消息列表、消息字典。

| 操作 | 外层对象 | 内部可变对象 | 修改内部对象的影响 |
|---|---|---|---|
| `b = a` | 与原对象相同 | 相同 | 原对象直接受影响 |
| `b = copy.copy(a)` | 新建 | 默认仍共享引用 | 修改共享内部对象会影响原对象 |
| `b = copy.deepcopy(a)` | 普通容器会新建 | 递归处理，通常分离 | 普通嵌套容器通常互不影响 |

**浅拷贝复制的是一层容器结构，不是把每个内部对象也重新创建。** 因此要区分两种操作：

- `b["messages"].append(...)`：修改内部列表，若列表共享，原状态也会变。
- `b["messages"] = 新列表`：替换副本外层字典中的引用，不会替换原字典里的引用。

同理，`b[0] = 100` 与 `b[0].append(100)` 不是一回事：前者改外层槽位，后者改槽位指向的内部对象。

对普通列表、字典，`is` 可以帮助判断两条引用是否指向同一个对象；`==` 主要比较值。**两个副本内容相等，不代表它们共享同一个对象。**

## 三、完整例子：分别观察浅拷贝和深拷贝

下面的 `state` 模拟一个 Agent 的简单会话状态，示例只涉及内置字典、列表和字符串。

```python
from copy import copy, deepcopy

state = {
    "messages": [{"content": "你好"}],
    "tools": ["search"],
}
alias = state
shallow = copy(state)
deep = deepcopy(state)

print(alias is state, shallow is state)  # True False
print(shallow["messages"] is state["messages"])  # True
print(deep["messages"] is state["messages"])  # False

shallow["messages"][0]["content"] = "已修改"
print(state["messages"][0]["content"])  # 已修改
print(deep["messages"][0]["content"])   # 你好

shallow["tools"] = ["calculator"]
print(state["tools"])  # ['search']

deep["messages"].append({"content": "独立追加"})
print(len(state["messages"]), len(deep["messages"]))  # 1 2
```

浅拷贝中的消息字典仍然与原状态共享，所以修改消息内容会影响原状态。但替换 `shallow["tools"]`，只是修改新字典自己的键值绑定，不会改变原来的工具列表。

深拷贝在修改发生前就已创建，所以它保留“你好”，后续追加消息也不会改变原消息列表。

实际选择时，可以按修改范围判断：

- 只需要改外层配置项，嵌套值保持只读：浅拷贝通常足够。
- 分支会修改已有的嵌套消息、参数或列表：需要复制被修改的对象，或对适合复制的纯数据状态使用深拷贝。
- 仅追加新消息，不修改旧消息：可以新建外层消息列表并共享旧消息，但必须保证旧消息之后不会被修改。

不要把数据库连接、模型客户端和纯数据状态混成一个大对象后盲目深拷贝，某些资源不可复制，另一些本来就应共享。

## 四、三个高频追问

**Q1：深拷贝会把所有东西都创建成新对象吗？**

不会。不可变对象可能被复用，函数、类等也有特定处理方式；自定义对象还能通过 `__copy__()`、`__deepcopy__()` 控制行为。因此，不能用“每一层的 id 必须全部不同”判断深拷贝是否正确。

**Q2：遇到循环引用，深拷贝会无限递归吗？**

标准 `deepcopy` 对正常支持的对象使用 `memo` 记录已复制对象，避免重复展开循环，并通常保留原对象图里的共享关系。自己实现 `__deepcopy__()` 时也要正确使用它，不能忽略循环引用。

例如，原数据中两个字段指向同一个列表，深拷贝后两个字段通常仍共同指向一个复制后的列表，并非强行拆成两个不同列表。

**Q3：深拷贝是不是更安全，应该默认都用？**

不是。它可能增加时间和内存开销，复制不应复制的状态，也不能代替锁、事务或持久化快照。其他线程正在修改对象时，不能仅靠深拷贝保证获得业务一致的状态。

复习时，先问自己：**我是在修改外层引用，还是在修改内部可变对象？** 这比死记“浅一层、深多层”更能解释代码结果。
