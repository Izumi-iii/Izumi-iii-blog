判断两字符串是否同构，本质是验证字符间是否存在严格的“一一对应”（双射关系）。若仅使用单个哈希表，容易拦截“一对多”而漏判“多对一”。通过维护一个映射字典与一个已访问集合，并依托清晰的分支状态，即可在单次遍历中高质高效完成双向约束校验。

<!-- more -->

## 题目与关键约束

[LeetCode 205. 同构字符串](https://leetcode.cn/problems/isomorphic-strings/) 要求判断字符串 `s` 和 `t` 是否同构。如果 `s` 中的字符可以按某种映射替换得到 `t`，则返回 `true`；否则返回 `false`。

- **替换一致性**：所有出现的相同字符都必须替换为同一个字符。
- **双射约束（关键）**：不能有两个不同的字符映射到同一个字符（禁止多对一），字符可以映射到它自身。
- **保序性**：保留字符的原有相对顺序。
- **数据规模**：$1 \le \text{len}(s) \le 5 \times 10^4$，且两字符串长度严格相等，字符为合法 ASCII 字符。

示例：`s = "egg", t = "add"` 返回 `true`；而 `s = "foo", t = "bar"` 以及 `s = "badc", t = "baba"` 均返回 `false`。

## 思路与推导

同构的核心在于**严格的一一映射（双射）**：既不能“一对多”，也不能“多对一”。

### 1. 单字典的漏洞
若仅建立从 `s` 到 `t` 的映射字典 `s2t`：
- 因为字典的 Key 具有唯一性，当遇到同一个字符试图映射到不同目标时，很容易被比对捕获（拦截“一对多”，如 `foo` 与 `bar`）。
- 但字典的 Value 允许重复，面对 `s = "badc", t = "baba"` 这类用例时，`'b' -> 'b'` 与 `'d' -> 'b'` 会各自新建 Key，单向字典无法感知 Value 已被占用，导致漏判“多对一”。

### 2. 字典 + 集合的流水线设计
为了杜绝 Value 冲突，同时避免维护两套字典，我们选择使用一个字典 `s2t` 配合一个集合 `visited`（记录已经被占用的目标字符）：
- **遇到已映射字符（`s_ch in s2t`）**：说明该字符已有专属绑定，仅需验证它本次对应的目标是否与先前的记录 `s2t[s_ch]` 一致。若不一致直接判错；若一致则安全通过，无需额外操作。
- **遇到新字符（`s_ch not in s2t`）**：
  - 先检查目标字符是否已被他人认领（`t_ch in visited`），若已被占则属于“多对一”违规，直接返回 `False`。
  - 若目标字符未被占用，则安全建立新映射 `s2t[s_ch] = t_ch`，并将 `t_ch` 添加入 `visited`。

使用 Python 内置的 `zip(s, t)` 即可同步完成逐位比对。

## 代码与复杂度

Python 完整实现代码如下：

```python
class Solution:
    def isIsomorphic(self, s: str, t: str) -> bool:
        s2t = {}
        visited = set()

        for s_ch, t_ch in zip(s, t):
            if s_ch in s2t:
                if s2t[s_ch] != t_ch:
                    return False
            elif t_ch in visited:
                return False
            else:
                s2t[s_ch] = t_ch
                visited.add(t_ch)

        return True
```

### 复杂度分析

设两字符串长度均为 $n$：

- **时间复杂度**：$O(n)$。使用 `zip` 遍历一次长度为 $n$ 的字符串，循环体内对字典和集合的查找、插入操作在平均情况下均为 $O(1)$，整体为线性时间。
- **空间复杂度**：$O(|\Sigma|)$。虽然分配了字典 `s2t` 与集合 `visited`，但由于字符均为 ASCII 字符，字符集大小 $|\Sigma| \le 256$。哈希表与集合中元素数量均有常数上限，额外辅助空间为常数级 $O(1)$。代码经静态逻辑推导与边界用例核验正确。

## 本次复盘

本次练习最具启发性的是**通过“角色状态拆分”理清多层分支的包含关系**：

- **原想法与初版混淆**：
  初版尝试将条件合并或将登记语句放在分支外层：
  ```python
  if s_ch in s2t:
      if s2t[s_ch] != t_ch:
          return False
  elif t_ch in visited:
      return False
  else:
      s2t[s_ch] = t_ch

  # 错误位置：外层无条件执行
  s2t[s_ch] = t_ch
  visited.add(t_ch)
  ```
- **反例与原因分析**：
  带入用例 `s = "egg", t = "add"`，在考察第 3 个位置 `('g', 'd')` 时，由于 `'g'` 已经在前一轮被绑定，本应走入 `s_ch in s2t` 分支顺利通过；但因为结尾在分支外无条件执行了 `visited.add(t_ch)`，导致老字符重复出现时被重复标记或在逻辑流上被后续逻辑误伤。
- **修正方案（“学生选座”模型）**：
  将字符映射拆解为生动的“选座”流程：
  1. **老学生**（`s_ch in s2t`）：只需核实是否坐对座位（`s2t[s_ch] != t_ch`），坐对则无需重新登记或复查；
  2. **新学生**：优先排查目标座位是否已有人（`elif t_ch in visited`），若被占即冲突；
  3. **空座入座**（`else`）：仅在此分支内登记字典并占用集合。
- **下次自检信号**：
  当一个循环体涉及“新状态初始化”和“已有状态比对”时，切忌把“初始化/状态打标”代码写在 `if-else` 的公用后置区域，必须严格限定在“新对象诞生”的分支内。
