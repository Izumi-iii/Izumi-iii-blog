## 题目与关键约束

- **平台与题号**：LeetCode [209. 长度最小的子数组](https://leetcode.cn/problems/minimum-size-subarray-sum/)
- **输入输出**：给定一个含有 $n$ 个正整数的数组 `nums` 和一个正整数 `target`，找出该数组中满足其总和大于等于目标值（$\text{sum} \ge \text{target}$）的长度最小的连续子数组，并返回其长度。如果不存在符合条件的子数组，返回 0。
- **关键约束**：
  - $1 \le \text{target} \le 10^9$
  - $1 \le \text{nums.length} \le 10^5$
  - $1 \le \text{nums}[i] \le 10^4$（**元素全为正整数**，这是滑动窗口具备区间和单调性的核心保证）
  - 无解时需返回 0

例如输入 `target = 7, nums = [2, 3, 1, 2, 4, 3]`，满足条件的最短连续子数组为 `[4, 3]`，返回其最小长度 2。

## 思路与推导

若采用朴素暴力解法，枚举所有子数组的起点与终点需 $O(N^2)$ 的时间复杂度，在 $N = 10^5$ 的数据规模下必然超时（TLE）。

### 单调性与滑动窗口模型

本题的一个隐藏黄金条件是：**所有元素均为正整数（$\text{nums}[i] > 0$）**。
- 当右边界向右扩张时，窗口内的总和 $s$ **严格单调递增**；
- 当左边界向右收缩时，窗口内的总和 $s$ **严格单调递减**。

这种区间和的单调性使得我们无需回溯指针，直接采用**同向双指针（滑动窗口）**求解：
1. **主动扩张（进窗）**：外层循环由右指针 `right` 驱动，逐个将元素纳入窗口并累加至总和 $s$。
2. **贪心收缩（缩窗）**：一旦当前窗口和满足 $s \ge \text{target}$，说明当前窗口是一个合法候选解。为了探寻是否存在更短的解，内层通过 `while` 循环不断将左端元素 `nums[left]` 移出窗口，尝试将窗口收缩到极限。
3. **状态更新顺序**：在缩窗过程中，必须**先记录当前合法窗口的长度**，然后再执行减除与左指针移动（`s -= nums[left]`, `left += 1`）。

### 避免手动维护双指针的边界陷阱

许多初学者（包括凭记忆手写时）常尝试使用单一 `while` 手动交替推进 `left` 和 `right`，这极易引发两类典型 Bug：
- 初始化 `right = 1` 会导致在单元素数组（如 `nums = [7]`）时发生 `IndexError`；
- 限制 `left < right` 会在单个元素即能满足 `target`（即最短长度为 1）时漏掉解。

采用 `for right in range(len(nums))` 外层驱动进窗、内层 `while` 条件缩窗的结构，能从语法层面天然消除数组越界与单元素边界的全部隐患。

## 代码与复杂度

```python
class Solution:
    def minSubArrayLen(self, target: int, nums: list[int]) -> int:
        left = 0
        s = 0
        min_len = float('inf')

        # 外层由 right 主动向右遍历，扩大窗口
        for right in range(len(nums)):
            s += nums[right]

            # 当窗口和满足 >= target 时，记录长度并尝试收缩左端
            while s >= target:
                min_len = min(min_len, right - left + 1)
                s -= nums[left]
                left += 1

        # 若未找到任何满足条件的子数组，返回 0
        return min_len if min_len != float('inf') else 0
```

- **时间复杂度**：$O(N)$，其中 $N$ 为数组长度。尽管包含嵌套的 `while` 循环，但每个元素在整个执行过程中最多进窗一次（`right` 递增）、最多出窗一次（`left` 递增），双指针的总移动次数不超过 $2N$，平均与最坏时间复杂度均为严格的 $O(N)$。
- **空间复杂度**：$O(1)$。仅维护了常数个辅助变量，无额外动态内存分配。

## 本次复盘

1. **原想法**：凭记忆编写时将条件拆分为 `if s < target ... elif s > target ... else:`，仅在 `s == target` 时才记录答案。
   - **原因**：误把本题与“两数之和”等精确匹配题目混淆，忽略了题面明确要求的“总和**大于等于** `target`”。
   - **修正**：只要 $s \ge \text{target}$ 即为合法窗口，需在该条件触发时更新最优长度并持续缩窗。
2. **原想法**：在缩窗内部先执行了 `left += 1`，随后才计算 `min_len = min(right - left + 1, min_len)`。
   - **反例**：提前移动 `left` 会使得长度公式计算的是“已经被剔除左端元素后的新窗口”，此时新窗口的总和可能已经不满足 $\ge \text{target}$，造成长度与状态不一致。
   - **修正**：严格遵循“先基于当前合法状态结算结果，再推进状态转移”的执行顺序。
3. **原想法**：使用 `left = 0, right = 1` 配合 `while left < right:` 手动调度双指针。
   - **原因**：试图在单个循环体内手动区分左移与右移分支，导致条件冗余且极难控制越界。
   - **修正**：迁移至标准的滑动窗口黄金模板——`for right` 负责开疆扩土进窗，内层 `while` 负责极限压缩合法窗口，结构精炼且具备完备的边界安全性。
